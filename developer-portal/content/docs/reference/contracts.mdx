The public repository also contains the current source candidate `reputation-registry-v3`,
`agentic-commerce-v4` and `sbtc-commerce-v3`. The v4/v3 escrow names are deployed only on testnet
under `ST16EWRC01S1SFWGBP63MW47VY8P3AYFA8VGEBGE5` and are not used by the production application.
They add a fixed 12 Bitcoin burn-block evaluator
window, a separate timeout-paid state, retryable reputation synchronization, source/job
namespacing, per-job sBTC token pinning and two-step ownership.

The earlier immutable `agentic-commerce-v3` and `sbtc-commerce-v2` contracts remain testnet-only
at 144 blocks as historical evidence.

Exact merge `b15544d601bd4e49610be854f7ad33a0af90c0a7` produced the current deployment.
`agentic-commerce-v4` and `sbtc-commerce-v3` confirmed at blocks 209312 and 209314; STX complete
passes 27/27 and official PoX-5 sBTC complete passes 30/30. The real-timeout job `u2` passes
preparation 20/20, settlement 12/12 and public-state verification 10/10. It settled at burn `11290`
in [tx `0x06537111…15bb9`](https://explorer.hiro.so/txid/0x06537111ef6c75d3c5d750154f97a3b4a0c233a84639583f7af18b2386915bb9?chain=testnet),
ending in `u6` with zero escrow, one exact 1,000-atomic-unit sBTC payout and no completion,
reputation or rating credit.

This documentation distinguishes testnet evidence from production activation. Construct candidate
transactions only against the source-verified testnet deployer and only when the integration
environment explicitly selects the v4/v3 names.

## Verification

Clone the public repository and run the signer-free verifier:

```bash
git clone https://github.com/PerkOS-xyz/PerkOS-Nayori.git
cd PerkOS-Nayori
npm ci
npm run verify:mainnet
```

The verifier compares source, exposed owners, canonical sBTC configuration and authorized
reputation callers. It requires no wallet or deployer key.
