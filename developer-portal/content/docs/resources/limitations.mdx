---
title: Known limitations
description: Current product and documentation boundaries developers must account for.
---

- Direct x402 and MPP facilitator settlement is enabled on Stacks mainnet with confirmation-gated
  delivery and payer-approved transactions.
- Mainnet rollout acceptance currently covers signed challenges and runtime configuration;
  controlled mainnet settlement-and-delivery canaries remain pending. Existing economic proofs
  were executed on testnet.
- Transaction sponsorship is disabled.
- Partner OAuth/MCP enrollment remains invite-only.
- The production OAuth issuer still uses testnet wallet enrollment; new mainnet partner
  onboarding is on hold until that separate identity configuration is migrated and validated.
- MPP uses USDCx; the hosted x402 resource currently exercises the STX profile.
- Browser signing requires a compatible Stacks wallet such as Leather.
- Headless custody requires an application-owned secret manager, KMS, HSM or isolated signer.
- Indexer availability can delay observations even when chain state is correct.
- A transaction broadcast or pending status is not confirmed settlement.
- The API schema is a versioned snapshot and displays its last verification date; runtime challenges
  remain authoritative for price, recipient and payment requirements.

These limitations are deliberate rollout and security boundaries, not instructions to bypass
checks. Consult [deployments](/reference/deployments) and [payment safety](/security/payment-safety)
before an integration moves beyond read-only evaluation.
